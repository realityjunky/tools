2. Quick start

Run these commands from the workspace root. The launcher sets the bundled CUDA library path, starts the guarded Python entry point, loads the local checkpoint, and writes Markdown.

1

Check the GPU

cd /home/hugo/AI
nvidia-smi
2

Parse one page

./Ovis/run_ocr.sh /path/to/page.png \
  --output /path/to/page.md
3

Inspect the result

sed -n '1,120p' /path/to/page.md
The input can be any image format supported by Pillow. Use one page per invocation for predictable memory usage.

3. Known-good test

Use the model’s downloaded performance image to verify the full local path without supplying your own document.

./Ovis/run_ocr.sh \
  Ovis/model/OvisOCR2/performance.png \
  --max-tokens 512 \
  --output /tmp/ovisocr2-check.md

sed -n '1,80p' /tmp/ovisocr2-check.md

The tested run loaded the Qwen3.5 architecture, selected Triton GDN prefill and FlashAttention, and returned Markdown successfully.

4. Command reference

./Ovis/run_ocr.sh IMAGE [OPTIONS]

Options:
  --model PATH       Override the default local checkpoint
  --output PATH      Write Markdown instead of printing it
  --max-tokens N     Maximum generated tokens; default: 16384

Example with a custom model path:

./Ovis/run_ocr.sh ./pages/contract.jpg \
  --model /home/hugo/AI/Ovis/model/OvisOCR2 \
  --max-tokens 8192 \
  --output ./results/contract.md

5. What the output means

  • Text is emitted in natural reading order as Markdown.
  • Formulas are requested as LaTeX.
  • Tables are requested as HTML table markup.
  • Optional visual-region <img> references are removed by the bundled runner so the output does not point to crops that were not saved. The official model card includes a separate crop-saving example when those regions are required.
  • OCR output is not authoritative. Review critical text, formulas, tables, and reading order manually.

6. First-run behavior and performance

First launch

The first process took about 206 seconds because vLLM compiled kernels, profiled memory, warmed the model, and captured CUDA graphs. This is expected.

Later launches

vLLM reuses its compile cache under ~/.cache/vllm. A new process still has to load the checkpoint and initialize the engine.

GPU budget

The runner follows the model card with one GPU and gpu_memory_utilization=0.8. The verified run reported about 9 GiB available KV-cache memory.

Slow or large pages

Start with --max-tokens 8192 for a bounded output. Close unrelated GPU jobs before processing high-resolution pages.

8. LiteLLM gateway integration

The current LiteLLM gate exposes OvisOCR2 as the premium alias ovisocr2. LiteLLM runs in Docker and forwards to the host-local vLLM OpenAI-compatible server at http://host.docker.internal:8001/v1. Portal-auth keeps it behind the vision API policy.

Set one shared secret in the LiteLLM .env and in the shell that starts vLLM:

export OVIS_VLLM_API_KEY='replace-with-a-long-random-value'
./Ovis/run_vllm_server.sh

After the local server is healthy, a gateway request uses the governed alias:

curl -sS http://127.0.0.1:4000/v1/chat/completions \
  -H "Authorization: Bearer $LITELLM_VIRTUAL_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"ovisocr2","messages":[{"role":"user","content":[{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}},{"type":"text","text":"Extract all readable content as Markdown."}]}],"max_tokens":16384}'
Operational gate: the local vLLM process must be running before LiteLLM can serve this alias. The source deployment also requires the normal clean origin/main and release-mount checks; this workspace change does not restart the live gateway.

9. Troubleshooting

If nvidia-smi fails: stop before starting OvisOCR2. A driver/library mismatch must be repaired and the host rebooted; a reboot disconnects sessions and stops running GPU jobs.

ImportError: libcudart.so.13

Use Ovis/run_ocr.sh, not the venv’s Python executable directly. The wrapper adds the CUDA libraries bundled with the installed vLLM stack.

./Ovis/run_ocr.sh /path/to/page.png --output /path/to/page.md

If a shell integration requires a direct Python call, export the same library paths first:

export LD_LIBRARY_PATH="/home/hugo/AI/Ovis/.venv/lib/python3.12/site-packages/nvidia/cu13/lib:/home/hugo/AI/Ovis/.venv/lib/python3.12/site-packages/torch/lib:${LD_LIBRARY_PATH:-}"
/home/hugo/AI/Ovis/.venv/bin/python /home/hugo/AI/Ovis/run_ocr.py /path/to/page.png

Driver repair, if the mismatch returns

uname -r
sudo apt-get update
sudo apt-get install --reinstall nvidia-driver-580 nvidia-utils-580 nvidia-dkms-580 linux-modules-nvidia-580-$(uname -r)
sudo reboot
nvidia-smi

Save work and check active sessions before rebooting. The kernel-module package name includes the running kernel version; there is no generic package named linux-modules-nvidia-580.

5. 如何理解输出

  • 正文按照自然阅读顺序输出为 Markdown。
  • 公式按提示输出为 LaTeX。
  • 表格按提示输出为 HTML table 标记。
  • 启动脚本默认移除可选的视觉区域 <img> 引用，避免结果指向没有保存的裁剪图。如果需要视觉区域，ModelScope 模型卡提供了保留标签并保存裁剪图的示例。
  • OCR 结果不是权威事实。关键文字、公式、表格和阅读顺序必须人工复核。

6. 首次启动与性能

第一次启动

第一次进程约耗时 206 秒，因为 vLLM 需要编译 kernel、分析显存、预热模型并捕获 CUDA graph。这属于正常现象。

后续启动

vLLM 会复用 ~/.cache/vllm 下的编译缓存，但每个新进程仍需要加载权重并初始化引擎。

显存预算

启动脚本遵循模型卡的单 GPU 和 gpu_memory_utilization=0.8 设置。已验证运行显示约 9 GiB 可用于 KV cache。

较慢或较大的页面

可以先使用 --max-tokens 8192 限制输出长度。处理高分辨率页面前请关闭其他 GPU 任务。

9. 故障排查

如果 nvidia-smi 失败：先不要启动 OvisOCR2。必须先修复 NVIDIA 驱动/库版本不一致并重启主机；重启会断开会话并停止运行中的 GPU 任务。

ImportError: libcudart.so.13

请使用 Ovis/run_ocr.sh，不要直接调用虚拟环境中的 Python。启动脚本会加入已安装 vLLM 栈自带的 CUDA 库目录。

./Ovis/run_ocr.sh /path/to/page.png --output /path/to/page.md

如果某个 shell 集成必须直接调用 Python，请先设置相同的动态库路径：

export LD_LIBRARY_PATH="/home/hugo/AI/Ovis/.venv/lib/python3.12/site-packages/nvidia/cu13/lib:/home/hugo/AI/Ovis/.venv/lib/python3.12/site-packages/torch/lib:${LD_LIBRARY_PATH:-}"
/home/hugo/AI/Ovis/.venv/bin/python /home/hugo/AI/Ovis/run_ocr.py /path/to/page.png

如果驱动版本不一致再次出现

uname -r
sudo apt-get update
sudo apt-get install --reinstall nvidia-driver-580 nvidia-utils-580 nvidia-dkms-580 linux-modules-nvidia-580-$(uname -r)
